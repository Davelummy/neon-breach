# Private free-for-all: local playable prototype

Implemented on `agent/community-foundation`, separate from the campaign. No merge, commit, push, cloud deployment, billing activation or installation. The already-present `ws` 8.21.1 package is now a pinned direct runtime dependency in the manifest/lockfile; nothing was downloaded.

## Play locally

Start `PORT=4176 npm run dev` from this repository. Open the main game on both devices. Sign in/create accounts using throwaway passwords on unencrypted local HTTP. Choose **Multiplayer · Create / join room** in the main menu. The full-screen multiplayer mode shares the game's signed-in session and returns to the menu with **Leave room**; it no longer requires navigating a separate prototype page. Campaign simulation/rendering and menu music suspend while this mode is open.

The agreed delivery target is **internet free-for-all for 2–8 players**, not a LAN-only product or battle royale. The current development preview still uses a local server: cross-network internet play has not been deployed. See `docs/online-multiplayer-deployment.md` for the deployment boundary and release gates. No paid service or cloud deployment is authorized in this phase.

Touch controls detect any coarse pointer or touch capability; hybrid devices can toggle them in the scoreboard. The joystick applies input immediately on press and resets on release/cancel. Joining focuses the game canvas instead of leaving keyboard focus in the room-code field. Drag-to-look works even when browser pointer lock is unavailable. These fixes are browser-tested, not a claim of physical iPad testing.

One player creates a room and chooses its initial arena and day/night lighting. Share the 10-character room code or use **Copy invite**; an invite pre-fills the code but never bypasses account authentication. Other players join that code. Everyone must reach the same backend (preview aliases can share one backend). The room starts its three-minute timer when at least two players are present. The next round rotates City Gate → Millennium Park → Jabi Lake, retains the room's day/night selection, resets round scores, and shows the previous winner. The timer pauses when only one player remains; this is a prototype rule, not competitive ranked play.

Room limit: eight players, sixteen simultaneous rooms in one local process. Those are hard caps, not proven operating capacity. Rounds and scoreboards are memory-only; leaving loses that player entry, empty rooms close, and restarting the host discards rooms/results. The host's laptop must stay awake. There is no automatic reconnect or persistent ranked board in this slice.

## Implemented game path

- Same-origin authenticated WebSocket upgrades use the existing account/session service. Anonymous/cross-origin and duplicate-account connections are rejected. Session validity is rechecked periodically.
- One fixed 20 Hz authoritative simulation per room, 10 Hz snapshots. Clients send sequenced bounded input—not positions, health, kills or score claims. Stale inputs stop movement; jumping continues under server gravity. Message size/rate and send backlog are bounded; heartbeat and room cleanup stop dead connections.
- Server-owned movement/collision, one automatic rifle, 30-round magazines, timed reload, fire cadence, line-of-sight/height hit checks, damage, kills and deaths. Four hits eliminate an unprotected player. There is no client-authoritative health endpoint.
- Three-second respawn, separation/visibility-aware spawn selection and two-second spawn protection that ends when firing. Spawn faces along the district road. Individual room/account identity remains internal; snapshots use ephemeral match IDs and usernames.
- Browser uses shared movement for bounded local prediction and replays unacknowledged input after server correction. Remote models interpolate between server snapshots. Walking accelerates toward the campaign's 2.9-unit/second speed; Q/L3 or touch Sprint selects 4.35, with slower aimed movement. Controls include keyboard/mouse, Shift fire, standard PS5 mapping, and touch move/look/fire/aim/reload/jet in either orientation. Disconnect/blur/rotation clear held input. Options/Escape opens or closes the match menu, releases mouse lock and sends neutral inputs while open. A visible warning says the live match continues; this is not a global pause.
- Taxis, yellow kekes and buses use the campaign's shared vehicle model factory. The server owns exclusive driver occupancy, safe entry/exit, acceleration/steering, collision, hull damage, wrecks and vehicle impact eliminations. E/Triangle or the contextual touch control enters/exits; jump boosts while driving. Vehicle speed is bounded separately from walking, and bullets gradually damage hulls rather than instantly exploding them. Driving snapshots interpolate; vehicles are refreshed on round rotation. Client-supplied vehicle positions, speed and identity are ignored.
- Dedicated lightweight WebGL2 renderer with campaign-shared tactical character rigs, textured rifle models, Abuja landmarks, skyline and roads. Collision blocks remain instanced; antialiasing and shadows stay disabled, with a capped drawing-buffer budget. No Canvas fallback; WebGL failure is reported in the lobby.
- A live in-room board, death countdown, confirmed-hit/kill feed, simple synthesized shot audio and a muzzle flash. Sound can be muted through the scoreboard controls. Final results are not written to Firebase or existing single-player leaderboards. Campaign save schema, vehicles, radio, API fallback and progression remain untouched.

## Safety and limitations

The development service defaults to direct HTTP. An optional exact HTTPS `NEON_PUBLIC_ORIGIN` makes socket origin validation and account cookie handling compatible with a future same-origin TLS reverse proxy; forwarded headers cannot override this setting. This configuration support is tested locally, but no internet/TLS/reverse-proxy deployment has been performed. Static Netlify hosting does not run this Node room service; the page reports unavailable instead of claiming multiplayer is connected. Do not expose this prototype publicly or use real-life/reused passwords over HTTP.

Shared vehicles and selectable day/night lighting are implemented in PvP. Radio, pickups, breakable glass, campaign mission objectives and multiple selectable weapons are not yet shared into multiplayer; the campaign retains its existing systems. The three arena collision layouts and landmark/model presentation are shared through `combat-presentation.js`, and vehicle models through `vehicle-presentation.js`; server authority and campaign saves remain separate. The match HUD exposes health, ammo, jet fuel, eliminations and deaths, with confirmed hit and damage feedback. Shared visuals do not imply full campaign feature parity or certified eight-player hardware performance.

### Mode parity

| Feature | Campaign | Multiplayer |
|---|---|---|
| Shared character/weapon/vehicle visuals and enemy map | Yes | Yes, opponents on map |
| Walking acceleration, sprint, aim, jet and controller vehicle entry | Yes | Yes, server validated |
| Day/night arenas | Mission selection | Room creator selects; persists across rounds |
| Options pause/menu | Pauses the local simulation | Stops your inputs; live match continues |
| Vehicles and impact damage | Existing campaign systems | Server-owned shared fleet |
| Mission/save, loadout, pickups, glass and vehicle radio | Existing campaign systems | Not ported into PvP |

These differences are intentional boundaries, not a claim that every campaign feature is available in multiplayer. Physical iPad/DualSense playtesting is still required.

### Player-facing interaction model

Campaign is a saved mission; multiplayer is a temporary room with rounds, opponents and automatic respawns. Shared controls and artwork support familiar shooter expectations, while lobby copy and contextual objectives explain these differences. A solo room provides safe movement/jet practice rather than pretending a competitive match has started. Health/ammo/jet labels and server-confirmed hit feedback support recognition instead of memorized status codes. Essential touch actions remain visible; account and room management sit in the labeled scoreboard disclosure. These choices apply Norman's conceptual-model, mapping, discoverability and feedback principles. Automated checks verify operation and bounds, not comprehension: representative desktop and iPad players still need to test joining without coaching, predicting respawn behavior, recognizing damage and leaving/rejoining.

The main entry now explicitly says “Play campaign”; multiplayer management is labeled “Match menu,” with a separate Scoreboard heading and Controls disclosure. This prevents a label that suggests only scores from hiding leaving, sound and control settings. Arrow keys implement the advertised WASD mapping. Invalid room codes are rejected before opening a connection, with the original input retained and an actionable inline explanation. Clipboard failure exposes a selectable invite link in the match menu rather than a disappearing combat-feed message. Low-ammo and jet-recharge hints appear only when relevant and match touch, keyboard or standard controller controls. No additional confirmation dialogs interrupt ordinary combat.

Both modes use a north-up arena map: a green directional arrow marks the player, and red dots mark living enemies/opponents throughout the arena, including behind cover. This is intentionally not fog-of-war. Dead opponents and pending campaign spawns are excluded. Campaign updates the map at most ten times per second; multiplayer uses its existing server snapshots and adds no network polling. The map is visible in tactical and full campaign HUDs and on touch screens. Opening the multiplayer match menu temporarily hides its map to keep management readable. Touch Aim now toggles like campaign Aim, while mouse/controller triggers remain held actions. Controller selection follows a connected controller receiving input rather than blindly taking slot zero; Triangle vehicle entry/exit remains edge-triggered. Browser tests use simulated standard-mapped controllers, so a physical DualSense/iPad retest remains necessary.

There is no rewind/lag compensation, interest management, advanced anti-cheat, reconnect reservation, ranked persistence, room sharding, migration to Firebase Auth, public matchmaking, production monitoring or abuse system. Server validation prevents basic position/health/fire-rate claims; it is not a claim of cheat-proof play. Network jitter, physical-device performance, eight simultaneous browsers and long sessions remain release gates. No 100,000-user or free-production-hosting promise is made.
